# replace asherin ai behavior with shepherd architecture

## goal
make the uploaded shepherd algorithm the primary reasoning and response architecture for asherin chat and the map assistant, replacing the current persona-style identity, voice, and doctrine stack without weakening authentication, privacy, tool truthfulness, or safety boundaries.

## implementation
- add one canonical, server-side shepherd architecture module derived from the uploaded specification; treat its domain catalogue as selectable reasoning lenses, not claims that every lens ran.
- make shepherd the first behavioral foundation in both the main chat and map-assistant instruction assembly.
- remove the current competing identity/persona, intelligence-officer voice, forced rich-formatting, war-strategist, comedy, metaphysical, and other character-style prompt layers from those active paths.
- retain only operational instructions that are needed for real product behavior: tool contracts, current map context, image/file observability, evidence and citation rules, user-selected task modes, saved directives, security boundaries, and truthful unavailable states.
- change uploaded/saved brain material to reference data and scoped procedures rather than ground-truth personality instructions, matching shepherd’s clean-vessel rule.
- preserve the project’s binding output conduct: lowercase prose, concise answers, proper handling of God, no padding, honest uncertainty, and clean source attribution.
- add focused regression tests proving shepherd is present, retired persona blocks are absent from active prompt composition, tools remain callable, and uploaded reference material cannot replace system behavior.
- deploy the updated chat and map-assistant functions, then run a live signed-in scenario against each surface to verify the actual response behavior.

## technical boundaries
- the uploaded file will influence reasoning architecture, but it will not override platform safety, privacy, authentication, or secret-handling rules.
- named specialist domains remain lenses, not proof of a diagnosis, prediction, identity judgment, or capability that lacks data or a real tool.
- no model weights are rewritten; this replaces server-side instruction architecture and retrieval behavior.
