codebase audit -> fixed operating narrative

the interface should never be more certain than its sources.

the previous build mixed UI, geometry, environment formulas, simulated telemetry, evidence intake, and interaction state inside one global script. that was fast to prototype, but the same pattern would eventually make every new feature capable of breaking unrelated features. the fixed build separates source ingestion, canonical state, rendering, AI provider transport, chat history, controlled actions, and UI presentation.

the AI operating narrative

the model does not receive a screenshot of the interface and guess what the software is doing. before every model call, asherin.soren constructs a canonical system snapshot containing the actual imported components, selected object, environment, view state, timeline position, source manifests, parser status, and connected model identity. the AI can then request specific real source contents through tools. read actions execute directly. navigation actions can execute automatically. scenario altering actions remain approval gated unless the user changes that policy.

for visual evidence, image bytes are passed to a vision capable connected model only when an image is actually registered. geometry measurements come from the geometry parser, not the vision model. telemetry values come from imported rows, not generated curves. missing source content stays missing.
